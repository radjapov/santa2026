# Santa 2026 — The Elf Calculator: контекст проекта

Участник — владелец репозитория. Общение на русском. Время пользователя — Ташкент (UTC+5).
Цель: удержать медаль (бронза → серебро). Финал 28 января 2027; объединение команд до 21 января.

## Правила работы
- Любая программа попадает в `best/best.json` только через `store.offer` / `store.py merge` (проверка `verifier.run`, только строго короче).
- Перед любым сабмитом: `python3 store.py export subs/submit.csv && python3 store.py check subs/submit.csv`.
  Отправка: `python3 tools/submit.py subs/submit.csv "описание"`. **Сабмит только с явного подтверждения пользователя.**
- Наш верификатор совпадает с официальным счётом до инструкции (проверено тремя сабмитами: 132 685, 132 670, 132 637).
- Делиться кодом вне команды приватно нельзя (правила). Метод до финала не публикуем.
- Репозиторий приватный. Kaggle-токен — в `~/.kaggle/access_token`, никогда не в чат и не в git.

## Задача (сверено с Data/Evaluation)
1000 головоломок, 48 регистров, инструкция `[op, i, j, d]`, op ∈ + - * /. Значения — целые 1..value_limit,
вычитание только если a > b, деление только нацело, чтение только определённых регистров. Цель покрыта, если её
значение появилось в любом регистре (включая стартовые). ≤4096 инструкций, ≤131072 байт в ячейке CSV.
Счёт = сумма длин. Одна неверная программа = весь сабмит отклонён.

## Что запущено (домашний ПК, WSL2 Ubuntu, i5-14400F 16 потоков, 32 ГБ, RTX 4060)
- `AUTOPUSH=1 JOBS=12 nohup tools/recomb_loop.sh > work/rc.log 2>&1 &` — LNS (elfopt) + CP-SAT перекомбинация, длины 60–180.
- `nohup python3 tools/sync_public.py --every 5400 --push > work/sync.log 2>&1 &` — автосинхронизация.
- Остановка: `touch work/STOP_RC`, `touch work/STOP_SYNC`. Пуш `best.json` — через `store.commit_push` (git-блокировка,
  при конфликте чужое хранилище сливается через верификатор). Облачная сессия тоже может пушить.

## Анализ (что выяснено)
- Семейства (`data/families_inferred.csv`): independent 242 головоломки / ~46.9k инструкций / 6.9 инстр. на цель
  (2.8 «личных» + 4.1 общих); shared 369 / ~40.6k / 4.1; mixed 226 / ~33.8k / 5.4; multiplicative 147 / ~11.6k / 3.0.
- Цели independent статистически случайны (структуры генератора нет). В shared/multiplicative слабый сигнал общих делителей.
- 74% программ independent используют все 48 регистров, но elfopt с 64/96 регистрами не находит ничего → узкое место
  не регистры, а локальность ходов поиска.
- До первой цели программы тратят 19% счёта (25.6k), в independent ~33 инструкции; «временных» там ~5.8 на головоломку.

## Закрытые гипотезы (не повторять)
- Статический общий пул (24–40 значений) + каждая цель из пула: цели стоят ≥7 инструкций → хуже текущих (proto/pool_probe.py).
- Пересборка разгона (prefix) с тем же интерфейсом: 0 улучшений на 40 independent (proto/prefix_resynth.py).
- Оптимизаторы Atakan (closure/frontier) на головоломках >180: 0 за 6 проходов.
- elfopt на головоломках >180 почти бесполезен (данные авторов LNS).
- Сильный оракул одной цели (21 ноя, cpp/oracle_probe.cpp): полный MITM стоимости 4 (S1∘S2, |S2|≈10–24 млн) и 5
  (S2∘S2, S1∘S3-цепочка, P∘(S1∘S2)) для целей с исключительным конусом ≥6 — 0 из 34. Конус 5 — S2∘S2 находит 13/18
  (так их и строили). Дорогие цели действительно дорогие; выигрыш только через совместную структуру.
- Публичный список провалов: ноутбук asteriospanoras «Best public score + dataset + fails» (E01–E17).
